# Add or Change Work

Part of [[Jobs/Jobs]]. Use for an explicitly assigned change or authorized implementation of an exact approved plan.

1. Read Current State, guardrails and the workstream's complete Key files/dependencies. Resolve the matching Latest/approved revision when applicable.
2. Record the exact direct assignment or approval source, finite acceptance and stop. A broader proposal remains unapproved. Architectural implementation readiness requires the ambiguity checklist's consequential choices to be resolved or explicitly outside the increment.
3. Reread the board, claim exact files and necessary shared-state locks, and establish isolation. Repository work uses an owned branch/worktree and project base branch; vault-only prose uses preservation/readback.
4. Post the truthful check-in from [[AGENTS]]. If context, authority or ownership is missing, resolve it before dependent edits.
5. Define compatibility, sequencing, recovery and rollback before changing shared data/interfaces or established workflows. Do the smallest authorized slice.
6. Verify the actual deliverable against acceptance. Prose needs source/link/readback checks; software needs relevant repository checks and the real affected flow with safe isolated data. Record actual results and unknowns, not assumed success.
7. Check applicable privacy, untrusted-input, access and side-effect boundaries. Current authority covers only the intended scope/target; prepare reviewable outputs before any separately gated action.
8. Update the affected current sources via [[Jobs/Update the Vault]], leave one meaningful handoff and present evidence through [[Jobs/Review a Change]]. Release or explicitly transfer ownership at the checkpoint.

Stop dependent work for conflicting guardrails, overlapping ownership, unclear compatibility, unverified shared data targets, a new external side effect/access scope or a material change to the approved outcome/risk. Return material design changes to plan review. Do not publish, merge or deliver externally merely because a checklist mentions that step.
