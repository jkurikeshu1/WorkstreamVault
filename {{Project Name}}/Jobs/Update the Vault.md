# Update the Vault

Part of [[Jobs/Jobs]]. Keep context accurate, small and useful.

## Boundaries

Actual deliverables and checks establish observed behavior. Detailed technical instructions belong with their source/repository. The vault holds mental models, boundaries, routing, active state, proposals, settled choices and meaningful handoffs. Link to detail instead of duplicating it. Read-only work ends in chat unless saving is part of the assignment.

## Authorized save procedure

1. Read the map, current rules and relevant workstream. Reread [[Current State]], claim exact files, and post the check-in.
2. Preserve an exact before-image in an appropriate local recovery location; keep it outside routine entry/context routing. Do not use it to accumulate private source archives. Compare expected current bytes before overwriting and reconcile concurrent edits.
3. Edit the canonical note once; link it from other places. For non-Git vault work do not modify a separate app checkout. Git-managed changes follow their own branch contract.
4. Read back from disk. A failed/uncertain save remains unsaved/unknown and blocks dependent work. Check links and source accuracy.
5. Distinguish correction received, saved with readback, and applied in a checked output. Revalidate affected dependent results after context changes.
6. Add one ordinary dated handoff for the meaningful change. Release claims/locks at the relevant checkpoint and identify unfinished work/next owner.

## Put the delta here

| Change | Canonical destination |
| --- | --- |
| Current objective/status, owner, stop or blocker | [[Current State]] |
| Workstream contract, actual boundary or Key files | Relevant workstream note |
| New settled invariant/cross-cutting choice | [[Architecture/Architecture Guardrails]] and [[Reference/Decision Log]], with evidence |
| Proposal or authorized saved review | Living plan; snapshot only for formal revision; registry/latest metadata |
| Meaningful result/check/next owner | One dated file via [[Daily Notes/Daily Notes]] |
| Approved workflow-rule change | Affected Job and entry contract; separately governed repo instructions only within their authorized scope |

Keep current state short; route superseded handoffs to clearly labeled history without losing approval, pause or recovery evidence. Prefer existing notes. Do not add a note for every turn, paste transcripts or copy sensitive communications. Repair inbound links on a rename. Archive superseded plans without deleting provenance.

For authorized new/adapted vault setup, follow [[Jobs/Create or Adapt a Project Vault]]. Agent entry, plan-review Job and proposal template must all carry the ambiguity requirement before setup is called complete.

One daily file per date uses [[Templates/Daily Note]], with a newest-first index and source-linked session entries. Keep unknown effort, duration and cost unknown. Do not create a reporting/recording system merely to maintain the vault.
